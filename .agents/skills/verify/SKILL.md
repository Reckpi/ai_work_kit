# verify

## 목적
만든 세션과 다른 눈으로 범위 충족·초과, 테스트, 깨지는 지점을 확인한다. 결과는 VERIFY.md에 남겨 제출물에 포함한다.

## 절차
1. **검토자 분리**: 가능하면 `reviewer` 커스텀 에이전트(`.codex/agents/reviewer.toml`, read-only)를 하나 띄워 아래 2~4를 수행시키고 보고를 받는다. 서브에이전트를 쓸 수 없으면 이 세션에서 직접 수행하되, 코드를 고치지 않고 보고만 한다.
2. `AGREEMENT.md`의 "만들 것 / 안 만들 것 / 성공 기준 / 제약"을 읽고, 코드·테스트가 각 항목을 충족하는지 **[충족 / 부분 / 미충족 / 범위초과]** 로 판정한다. 각 판정에 근거 파일·줄을 적는다.
3. `pytest -q`를 실행하고 출력을 그대로 인용한다. 서버 실행 명령이 에러 없이 뜨는지도 확인한다.
4. 깨질 수 있는 지점 **3개 이내**: 입력 이상값(빈 파일·결측·형식 오류), 경계값, 대용량, 보안(경로·입력 신뢰). 각각 "지점 / 왜 위험한가 / 어떻게 검증·수정하나" 3줄.
5. 결과를 `VERIFY.md`에 아래 형식으로 저장한다.

## VERIFY.md 형식
```
# VERIFY — <시각>
## 합의 대비 판정
| 항목 | 판정 | 근거 |
## 테스트 실행 결과
<pytest 출력>
## 약점 3개
1. 지점 / 위험 / 다음 검증
## 수정 권고 (우선순위 순, 각 1줄)
```

## 이후
사용자가 수정 항목을 고르면 그것만 고치고, 다시 `pytest -q` → 커밋 제안. 범위 밖 "개선"은 VERIFY.md 권고에만 남기고 구현하지 않는다.
