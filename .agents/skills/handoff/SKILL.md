# handoff

## 목적
다음 사람(또는 다음 세션)이 이 작업 공간만 보고 10분 안에 이어받을 수 있게 한다. 동시에 후속 서술형 답변의 재료(결정 이유·약점)를 정리한다.

## 절차
1. `AGREEMENT.md`, `VERIFY.md`, `git log --oneline`, 코드와 테스트를 읽는다.
2. `HANDOFF.md`의 1~8번을 채운다.
   - "주요 결정과 이유"는 **git log와 AGREEMENT에 근거가 있는 것만**. 각 결정에 버린 대안을 1개씩 적는다.
   - "알려진 약점 3개"는 VERIFY.md에서 가져오되, 수정된 것은 빼고 남은 것만.
   - "범위 밖 요청"은 INTERVIEW/DM에서 나왔지만 안 만든 것.
3. `README.md` 맨 아래에 `## 실행 방법` 섹션이 없으면 추가한다(설치 → 실행 → Browser 미리보기 PORT). 기존 README 본문은 수정하지 않는다.
4. `git status`를 실행해 추적되지 않은 파일을 나열하고, 포함할 것/제외할 것(캐시·대용량·비밀값)을 구분해 보고한다. `.env`·키·토큰이 있으면 경고한다.
5. 최종 커밋 메시지 초안을 제안한다: `docs: handoff and verification — <한 줄 요약>`. 실행은 사용자 확인 후.

## 출력
- `HANDOFF.md`, 갱신된 `README.md`
- 미추적 파일 목록과 최종 커밋 제안

## 하지 않을 것
- 코드 수정. 이 단계에서 발견한 버그는 HANDOFF "다음에 할 일"에 적는다.
